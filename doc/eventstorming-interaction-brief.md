# Esbuddy：让 UI 服务于 EventStorming

日期：2026-10-17

状态：交互设计提案，第一轮核心操作已实现，尚待用户体验反馈；
不是完整视觉规范，不改变现有建模语法。

## 1. 产品应该模拟什么

不是模拟纸的全部物理细节，也不是把流程图节点画成便利贴。
应模拟的是一群人借助可移动、可书写的共同材料来理解业务的过程：

- 每个人都能直接贡献，而不是围观一个操作者画图。
- 每条业务事实可以独立提出、移动、修改和讨论。
- 通过排列、附着、标记、连接，让理解逐步显现。
- 允许尚未形成共识的内容存在，不强迫所有表达立即完备。
- 让大家知道正在讨论什么，但不剥夺个人探索和查看的自由。

EventStorming 官方将它定义为协作探索复杂业务领域的灵活工作坊形式，
而不是某一种图表语言。[1]

因此，对包豪斯的借鉴应落实为：
**研究这些工作如何发生，再让形式表达它们的结构与关系。**

## 2. 从工作坊方法推导交互约束

### 人人有笔，而不只是“支持多人连接”

官方的 One person/One Marker 强调并行贡献，
并指出小阻碍也会显著影响工作坊的流动。[2]

对产品的要求：

- 新增、命名、落位应该是短而连续的操作，不反复切换到远处的工具面板。
- 不以主持人或单一操作者为默认交互中心。
- 他人的操作可见，但不自动把我的视角、选中或当前输入带走。
- 临时提示不能遮住正在输入的内容；撤销要让人清楚自己撤销了什么。

### 墙足够大，但人仍需要方位

Unlimited Modelling Space 的目标不是无限坐标本身，
而是避免空间与材料稀缺使人过早省略内容、收缩问题范围。[3]

对产品的要求：

- 不把故事限制在预设卡片网格或固定大小的流程容器里。
- 保留空间记忆；不能为了“整齐”自动重排整个板。
- 远近查看、局部返回、搜索定位要帮助人保持方位。
- 不应通过不断缩小文字来制造“所有东西都装得下”的假象。

### 先贡献，再逐步组织

Chaotic Exploration 允许不同视角、不同粒度甚至不一致的叙述出现；
这种不一致本身是发现问题的材料，并不是一开始就该消灭的噪声。[4]

Incremental notation 则主张只提供当前需要的指导，
逐渐引入符号，而不是一次解释全部建模语言。[5]

对产品的要求：

- 新手先能写出一个事件，不必先掌握聚合、策略、读模型和编译器。
- 工具可以逐步呈现或按上下文推荐，但不能用强制步骤锁死专家操作。
- 未完成的模型仍可以保存、重排和讨论。
- 现有合法连接与附着规则继续有效；“尚未完备”不应成为写下一张便签的阻碍。
- 校验用于审视模型，而不是让整个工作坊持续处于红色警报中。

### 数字环境不是纸墙的逐项复刻

官方的 Frame Sorting 专门讨论：
线上拖动、排序便利贴与线下不同，需要调整组织方式。[6]

因此，模拟的对象是协作与认知过程，不是所有手部动作。
搜索、键盘、撤销、明确的附着预览等数字能力可以优于纸墙，
但应服务于参与、理解与修正，而不是不断增加控件。

## 3. 便利贴应是一种“可操作材料”

纸纹、色块和投影只是材料感的一部分。
更关键的是，用户能否从外观判断它能做什么，以及刚刚发生了什么。

| 情境 | 用户需要知道什么 | UI 应传达什么 |
| --- | --- | --- |
| 静置 | 这是什么业务事实 | 业务文字优先，类型可辨识，空备注和控件不抢占阅读 |
| 准备操作 | 我可以在哪里写、在哪里拿起 | 明确但克制的编辑与移动线索，不要求猜手势 |
| 选中 | 接下来的命令作用于谁 | 局部选择标记；不把“选中”自动表现成已经拿起 |
| 编辑 | 键盘正在写哪张便签 | 清晰输入焦点，文字可见，其他快捷键不会误触发 |
| 拖动 | 我移动的是单张还是一个组合 | 轻微抬起、组合随动、明确落位，不做装饰性抖动 |
| 可以附着 | 松手后会产生什么关系 | 显示唯一合法目标及关系；不能只泛泛发光 |
| 已附着 | 这不是偶然重叠 | 可辨识的依附关系；移动目标时组合跟随 |
| 正在解除附着 | 松手后关联会解除 | 与加入不同的可预期反馈，操作可撤销 |
| 只读 | 我可以阅读、查看，但不能修改 | 不显示误导性的编辑、拖动和连接暗示 |

由此才讨论阴影、边界、间距和字重：

- 轻微投影若表达“正在拿起”，就有交互目的；所有状态都厚重悬浮则没有区分作用。
- 类型色帮助扫读；便签正文才承载业务叙事，不应退化为一个小卡片的标题。
- 空备注占位在整张板上重复出现会竞争注意力，需验证是否只在准备编辑时提示。
- 连接点可按需出现，但“隐藏后更像纸”不足以证明设计合理，还必须让初次使用者找得到。
- 圆角或直角不先定为信条，应结合材料辨识、命中范围和边界可读性决定。

## 4. 墙上的位置、容器和关系不能混为一谈

### 排列不等于因果

左到右的排列可以支持时间叙述，
但不意味着系统应自动推断每对相邻事件之间存在因果或生成连接。
并行、分支和暂时未排序的内容也应保留表达空间。

### 重叠不必然是附着

当前实现已经通过唯一合法目标与显式 `boundTo` 区分附着和几何重叠。
交互设计应把这个承诺表达出来：
有唯一目标时显示将产生的关系；目标不确定时不悄悄挑选一个。
不能为了“像真实贴纸”而让偶然相碰改变语义。

### 视觉分簇不等于领域聚合

工作坊中，为了整理故事而圈出一簇内容，
不一定是在宣布一个 DDD 聚合。
当前聚合成员关系是显式的，成员类型也有约束，不能把它当通用收纳框。
未来若需要普通视觉分区，应与领域聚合区分；这里不建议直接修改现有数据模型。

当前语法是 Esbuddy 支持的可编译表示，
不是声称 EventStorming 的全部合理表达都已经被这一套语法覆盖。

## 5. 讨论与共同注意力

热点是让讨论可以稍后继续的材料，不只是红色便签。
官方 Rush to the goal 建议先形成可见的基线，
同时用 Hot Spots 保留异议、边界情况与尚待展开的问题。[7]

据此，热点应容易在讨论发生的位置提出，
投票应明确“投给哪个问题”“我是否已经投过”“如何撤回”，
而不是脱离上下文的统计装饰。
票数表达关注或优先级，不自动等同于问题已经解决或模型已经达成共识。

多人光标也不等于共同注意力：

- 正在查看、选中、编辑与邀请大家关注，是不同的意图。
- 提醒别人看某处，不应默认强制移动所有人的视角。
- 个人选中、远端选中、附着预览和诊断，要避免使用不可区分的描边或发光。
- 反馈应告诉人“谁在做什么”，而不是仅仅增加更多颜色。

这些是交互需要区分的情况，不意味着第一版应立即新增所有协作功能。

## 6. 从现有实现出发，而不是推倒重来

现有代码已经有值得保留的基础：

- 快捷键在指针位置添加便签，工具按钮在视图中心添加便签。
- 便签内可以编辑标题与备注。
- 附着目标预览、目标移动时依附对象跟随、拖离后解除关联。
- 聚合成员的显式关系与随动、热点投票、Yjs 协作和撤销。
- 编译诊断由检查入口打开，而不是默认覆盖整个画布。

下一步要研究的是这些能力的可发现性与连续性，而不只是功能是否存在：

- 添加后还需要多少次操作才能真正写下业务事件？
- 便签出现在预期的位置吗？是否要先找它，再选中、再双击？
- 未阅读帮助的人，能否发现连线、附着和解除附着？
- 拖动组合、单张移动与移出聚合的区别，是否能在操作前预知？
- 手机上的长按、平移和编辑，会不会竞争同一个手势？
- 一张高密度真实示例板上，类型标签、备注、控件和状态是否压过了业务内容？

## 7. 第一份原型的范围与判断方式

先不扩展登录页或品牌图形，也不引入强制阶段向导。
用现有真实示例板，加一个小型未完成故事，展示三段完整交互：

1. **写下一件事：** 提出事件、输入内容、落位、连续补充下一件事。
2. **建立并修正理解：** 重排便签、附着参与者、移动组合、解除关联、撤销。
3. **留下讨论：** 原位标记热点、投票与撤回、按需打开诊断并回到相关便签。

每段原型都标注：
起点、意图、动作、可见反馈、最终状态，以及误操作后的恢复。
不能只提供一张静态美化截图。

初步验收问题：

- 不读完整教程，是否能完成首次贡献？
- 操作时是否需要频繁离开讨论位置去找工具？
- 松手之前，能否预知将移动谁、附着到谁或解除什么？
- 排列与移动是否保留了业务含义和参与者的空间记忆？
- 不完整的叙述是否可以继续讨论，而不是被工具提前要求“正确”？
- 便签、连线、结构与协作反馈并存时，业务故事是否仍最先被看见？

完成这些验证之后，再让网格、比例、字体、色彩、材质成为稳定的表达系统。
这比在界面上添加包豪斯符号，更接近以方法决定形式。

## 8. 第一轮实现边界

- 工具区取纸后，在画布选择落点并直接书写；E 等快捷键在指针处直接开始写。
- 新便签在确认前是本地草稿。Enter、完成按钮或非空失焦确认；
  Escape、取消按钮或空内容失焦不产生共享便签，也不产生撤销记录。
- 输入法组词时的 Enter 不提交；Shift+Enter 可以换行。
  远景下书写字号维持可读，不通过强制跳转视角解决输入问题。
- 新增便签的内容与附着关系作为一次操作写入，能一次撤销。
  失焦保存不会抢走用户接下来点击的对象的选择状态。
- 静置不重复显示空备注；选中与拿起分开表达。
  编辑、备注、解除关联和层级操作靠近选中的便签，多选时提供聚合操作。
- 附着前给出目标与关系反馈；已附着显示关联标记。
  拖离和局部解除均保留位置，并支持撤销；拖动途中暂停也不会把一次动作拆成多次撤销。
- 仍保留所有类型、合法连接、投票与只读视图。导出与结构工具可通过搜索访问。
  不新增强制工作坊阶段，不自动重排版面，也不重新设计首页与品牌。

浏览器回归检查与真实用户的工作坊体验验证是两件事。
这一轮只能确认上述交互路径能按预期执行，还不能据此宣称它已被证明更易学或更高效。
